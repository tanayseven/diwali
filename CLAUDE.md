# Diwali Celebration

See README.md for what the app does and how to run, build and deploy it.

## Releases

- Releases are tagged with their date, `YYYY.MM.DD` (for example `2026.10.30`). Never use semantic version tags like `v1.0.0`.
- A second release on the same day is `YYYY.MM.DD.2`, then `.3`, and so on. The first release of a day has no number.
- Tags are made automatically: `.github/workflows/nightly-tag.yml` runs at 11:30 PM IST (18:00 UTC) and tags `main` with the IST date, only if something that goes into the app differs from the newest date tag. Its `not_built` list names what doesn't count (docs, `.github`, `scripts`, `.idea`, `.gitignore`); add to it anything new that isn't built into the app, and everything else counts. It numbers the tag if the day already has one.
- A tag pushed from a workflow doesn't start other workflows, so the nightly workflow calls `.github/workflows/android.yml` and `.github/workflows/desktop.yml` itself. Both also run when a date tag is pushed by hand: one builds the Android APK, the other the Windows, macOS and Linux apps with Wails (`desktop/package.sh`), and both attach what they build to the same GitHub release for the tag, whichever gets there first creating it. Other tags don't trigger them.
- The Android version comes from the tag, through `RELEASE_TAG` in `android/app/build.gradle`: the version name is the tag, and the version code is the days since 1 January 2026 times 100, plus the day's release number (`2026.11.04.3` is `30703`). Google Play rejected `YYYYMMDD` times 100 as too close to its limit of 2,100,000,000. The desktop apps take it from `RELEASE_TAG` too, in `desktop/package.sh`. Builds without a tag are versioned `dev`.
- `android.yml` also publishes the bundle to Google Play when the `PLAY_SERVICE_ACCOUNT_JSON` secret is set: `r0adkll/upload-google-play` (pinned to a commit SHA, as it's handed the key; keep it pinned) uploads it and releases it to internal testing, then `scripts/release/play-release.sh` releases the same version code through Play's API, without uploading it again, as Play refuses a version code it already has: fully to closed (`alpha`) testing, each track in an edit of its own, so one Play refuses doesn't stop the rest. It's run from the workflow's own commit, not the tag's, and `android.yml` can be run by hand for a tag to build and publish it again. It runs after the GitHub release, so a Play failure never stops the APK being attached. Open testing (`beta`) and production (`production:0.2`, a staged rollout to 20%) are left out of its tracks until Google gives the new personal account access to them, as Play refuses both with "Precondition check failed" until then; add them back once it does. Rolling out to everyone, or halting a rollout, is done by hand in Play Console.
- Each date tag is on a commit of its own, `Release <tag>`, made by the nightly workflow, with the version in `android/version.properties` and what's new in `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt`, as F-Droid reads both from the tagged source. Only CI writes those; never edit them by hand. `scripts/release/version.sh` and `android/app/build.gradle` both work out the version code from a tag, so change them together. `fastlane/` holds the store's text and images, and `fdroid/` F-Droid's build recipe, neither of which makes a release.
- The nightly workflow also calls `.github/workflows/itch.yml` once the Android and desktop builds are done, which pushes the release to itch.io with butler (`scripts/release/itch.sh`): the browser build (`npm run build:itch`) and every file of the GitHub release, each to a channel of its own. butler's pinned by version and checksum in that workflow, as it isn't in mise's registry. Change `itch.sh` with the file names `desktop/package.sh` and `android.yml` give their builds.

## Tools

- Every tool is pinned to an exact version in `mise.toml` and locked in `mise.lock`, which installs must match. After adding a tool or changing a version, run `mise lock` and commit both files. Keep new versions at least a week old (`minimum_release_age`).
- Generated files are made with `mise run generate` (or `generate:i18n`, `generate:icons`), not by hand.
